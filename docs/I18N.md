# Interface FR / EN

## Comportement

- Le sélecteur est présent sur l’accueil, les pages d’authentification et le header du dashboard.
- Paramètres contient « Langue de l’interface ».
- Hors connexion, le choix est mémorisé sur ce navigateur dans `mdp:locale`. Le français est le défaut.
- À l’inscription, la langue choisie est transmise à l’API.
- Après connexion, `GET /auth/me` fournit la langue du compte. Elle prend priorité sur le choix local.
- En session, changer de langue enregistre uniquement `locale` via `PATCH /auth/me`, puis actualise le cache du profil et l’interface sans navigation.
- Les comptes existants sont initialisés en français.
- Aucun contenu utilisateur (titres de tâches, notes, catégories personnelles) n’est traduit automatiquement.

## Catalogues et appels

Les traductions sont dans :
- `client/src/locales/fr.json`
- `client/src/locales/en.json`

Les deux fichiers contiennent exactement les mêmes clés explicites. Les clés sont regroupées par préfixe : `common.*`, `navigation.*`, `auth.*`, `tasks.*`, `settings.*`, `messages.*`. Les anciens dictionnaires TypeScript à clés françaises ont été retirés.

Exemple de contenu dans les fichiers JSON :

```json
{
  "common.save": "Enregistrer",
  "navigation.tasks": "Tâches",
  "tasks.createCount": "Créer {count} tâches"
}
```

Le fichier anglais définit les mêmes clés avec `Save`, `Tasks` et `Create {count} tasks`.

Dans un composant React :

```tsx
import { useTranslator } from "@/i18n/provider";

const t = useTranslator();
return <button>{t("common.save")}</button>;
// Interpolation : t("tasks.createCount", { count: 3 })
```

- Moteur pur : `client/src/i18n/translate.ts` ; il exporte aussi le type `TranslationKey`.
- Provider : `client/src/i18n/provider.tsx` ; conserve la préférence du compte et le choix navigateur.
- `Localized` affiche une clé dynamique de catalogue dans les composants existants. Les nouveaux appels doivent utiliser des clés explicites.
- Une clé absente d’EN utilise FR, puis la clé elle-même. Ne pas passer de contenu utilisateur à `t`.
- Une nouvelle traduction doit être ajoutée aux deux JSON ; le test vérifie la parité de leurs clés.
- Les formats Intl et les calendriers suivent la langue ; le fuseau horaire reste indépendant.
- Avant déploiement de l’API : `npm run migration:run` dans `api/` (migration `1758297300000-UserLocale`, déjà appliquée en local).
- Les communications externes côté serveur et certaines erreurs fournisseurs ne sont pas traduites par ce moteur client ; leur localisation reste distincte.

## Validation

- 130 tests client, 215 tests API.
- Test PostgreSQL dédié en transaction annulée : défaut FR, sauvegarde EN et isolation entre deux comptes.
- Basculement visuel FR/EN vérifié sur accueil et connexion, sans modifier de compte réel.
- Parcours connecté à revalider dans le navigateur : choisir EN dans Paramètres, déconnexion/reconnexion, vérifier EN sur les autres appareils.
- Le lint global signale encore des erreurs React préexistantes dans les anciens effets/composants de graphiques ; les nouveaux composants de langue sont vérifiés séparément.
